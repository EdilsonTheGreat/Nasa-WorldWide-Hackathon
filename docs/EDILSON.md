## 1. Context in 1 minute
On long missions, microgravity shifts fluids toward the head, and the retina around the optic nerve thickens (SANS). Often the astronaut feels nothing.
Our app runs a quick test (Amsler grid, near acuity, 4 questions) and records OCT (retinal thickness, in µm). The **engine** decides the traffic-light color:

- **green** (`verde`): within expectations → next test in a week
- **yellow** (`amarelo`): monitor → repeat in 3 days, backup glasses, check CO₂
- **red** (`vermelho`): notify the flight surgeon now → package ready + plan while waiting

Each signal (OCT, Amsler, acuity) gets a color; **the final color is the worst of the three**.

## 3. The data you receive (already exists, generated by the simulator)
`app/dados.js` defines:

**`window.FAIXAS`**
```js
{
  p10: [/*181 numbers, index = day 0..180*/], p50: [...], p90: [...], p97: [...], // expected Δ% per day
  subida_rapida: [ {de: 0, ate: 10, taxa_p97_pct_dia: 0.6069}, {de: 10, ate: 30, ...}, ... ],
  calendario_oct: [0, 10, 30, 60, 90, 120, 150],
  s_min_um: 5.0
}
```
Example on day 90: `p10=4.614, p50=9.185, p90=15.033, p97=16.99`.

**`window.ASTRONAUTAS`**: one record per astronaut per test day:
```js
{ astronauta_id: "DEMO_C", perfil: "demo_vermelho", dia: 91, oct_um: null,
  amsler_zonas: [2, 4, 5], amsler_centro: 1, acuidade_linha: 8, melhora_com_oculos: 0,
  perg_focar: 2, perg_contraste: 3, perg_dor_cabeca: 3, perg_visao_dupla: 3 }
```
- `oct_um` only exists on days 0, 10, 30, 60, 90, 120, 150 (otherwise `null`). **Day 0 = baseline (pre-flight).**
- Quick test (Amsler, acuity, questions) on days that are multiples of 7 (otherwise `null`).
- `amsler_zonas`: 3×3 grid numbered `0 1 2 / 3 4 5 / 6 7 8`; **4 = center**. `[]` = no distortions.
- `acuidade_linha`: smallest line read (10 = normal; **lower = worse**).

## 4. `motor.js` functions (exact signatures: Marllon's app calls them like this)

### 4.1 `Motor.corOCT(medicoes, faixas)`
- `medicoes`: array `[{dia, oct_um}, ...]` **sorted by day**, OCTs only. The **first** is the baseline. The last is the measurement to evaluate.
- Returns `{cor, delta_pct, z, motivo}`.

Algorithm:
```
if medicoes.length < 2 → { cor: "a_calibrar", delta_pct: 0, z: 0, motivo: "Primeiro OCT guardado como linha de base." }
b = medicoes[0].oct_um ; x = last.oct_um ; d = min(last.dia, 180)
delta = (x − b) / b × 100
cor = delta > p97[d] ? "vermelho" : delta > p90[d] ? "amarelo" : "verde"

// rapid rise (only escalates yellow → red; avoids alarms from OCT noise)
prev = second-to-last measurement ; d0 = prev.dia
rate = (delta − (prev.oct_um − b)/b×100) / (d − d0)        // percentage points per day
lim = faixas.subida_rapida.find(t => t.de <= d0 && d <= t.ate)?.taxa_p97_pct_dia
if cor == "amarelo" and lim exists and rate > lim → cor = "vermelho", motivo = "Subida rápida desde o último OCT."

// z = distance from expected on that day (informational, for display)
spread = max((p90[d] − p10[d]) / 2.563, 0.5)
z = (delta − p50[d]) / spread
```
Round `delta_pct` and `z` to 1 decimal place. `motivo` is in Portuguese (the interface translates it), e.g. `"Retina +16.0% (esperado até +15.0% ao dia 90)."` ("Retina +16.0% (expected up to +15.0% on day 90).")

### 4.2 `Motor.corAmsler(zonasBase, zonasHoje, regras)`
- Arrays of integers 0–8. For a new user, `zonasBase = []`.
- `novas = zonasHoje − zonasBase` (set difference).
- `novas` contains `regras.amsler.zona_centro` (4) → **red**; `novas` not empty → **yellow**; otherwise **green**.
- Returns `{cor, zonas_novas, motivo}`.

### 4.3 `Motor.corAcuidade(linhaBase, linhaHoje, melhoraComOculos, regras)`
- `perda = linhaBase − linhaHoje` (loss).
- `perda >= regras.acuidade.perda_amarelo_linhas` (1) and `melhoraComOculos === 0` → **red**
- `perda >= regras.acuidade.perda_amarelo_linhas` → **yellow**; otherwise **green**.
- Returns `{cor, perda, motivo}`.

### 4.4 `Motor.piorCor(cores)`
Order: `a_calibrar` < `verde` < `amarelo` < `vermelho`. Returns the worst.

### 4.5 `Motor.avaliar(registos, dia, faixas, regras)`: the function the app uses
- `registos`: all records of **one** astronaut (`ASTRONAUTAS` format).
- Uses only records with `dia <= dia`.
  - OCT: all `oct_um != null` → `corOCT`.
  - Quick test: **baseline** = first record with `acuidade_linha != null`; **today** = the last one up to `dia`. If only one exists (the current one), acuity gives `verde` (it is the baseline) and Amsler is compared against a grid with no distortions (`corAmsler([], zonas)`): distortions on the 1st test give yellow or red.
- Returns:
```js
{ cor_final, sinais: { oct: {...}, amsler: {...}, acuidade: {...} },
  texto: regras.textos[cor_final].mensagem,            // sentence for the astronaut
  proximo_teste_dias: regras.textos[cor_final].proximo_teste_dias,
  motivos: [ /* reasons from the signals that are not green */ ] }
```
- If `cor_final` is `a_calibrar`, use `regras.textos.a_calibrar`.

### 4.7 `Motor.prontidao(respostas, regras)`
Status of the pre-exam questionnaire (VISION GUARD), separate from the clinical color. Rules in `REGRAS.prontidao` (question → option → `e`: verde/amarelo/vermelho, `m`: caveat; the `alteracao_visual` question is multiple choice and only produces `alerta_clinico`). Final status = the worst. Tests 21 and 22.

### 4.6 `Motor.registosDe(astronautaId, astronautas)`
Filters and sorts by day. Shortcut for the app.
